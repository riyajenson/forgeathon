# Forge editor and harness contracts

**REVIEWED WITH CHANGES R1-R5** | Application protocol **0.4.6**

The VS Code extension captures user input, displays real harness activity, records review decisions, applies approved edits, and owns undo. Claude’s adapter translates the contract to local TrueForge sessions, MCP operations, retrieval, approvals, retries, and fallback. TrueForge owns model interaction and the agent loop. These declarations specify application behavior and do not establish SDK compatibility.

Codex drafted this revision. Both owners review changes through the user before either consumes a changed schema. Use an exact version match for this initial release. Reject mismatches before starting work. Bump the minor version for incompatible changes during 0.x, including changed semantics or event variants. Reserve patch versions for compatible corrections and coordinate rollout even for patches.

## Data and lifecycle

Transport data consists of JSON records, arrays, strings, finite numbers, booleans and null. Omit absent optional fields. Validate received data at runtime, including discriminants, integer ranges, IDs, and workspace containment after resolving symlinks. Bind each session to one trusted local workspace. Paths inside that root use relative POSIX syntax. Never put credentials, authorization headers, raw SDK exceptions, or secret-bearing command output into events or logs. Sanitize display text, including tool summaries and trace URLs. If source or proposal content contains a secret that cannot safely be transmitted verbatim, refuse with a sanitized error. Redacting executable content would invalidate review.

Request IDs correlate replies and retries. Generate the turn ID before submission. A duplicate submission or review with the same identity and contents must not execute twice. Conflicting reuse fails. A successful submission means the adapter has accepted the turn. Later failures are events. Before submission succeeds, return a failed response for a rejected request. Operational errors carry a safe message, retryability and observed workspace effect. Use unknown if the outcome cannot be established.

Within a turn, sequence starts at 1 and increases by one in delivery order. Subscribe from 0 for the initial stream. The adapter buffers from submission, including immediate failures. Resume strictly after the supplied cursor, deduplicate by session/turn/sequence, and report stream_gap if history is unavailable. A stream error is not evidence that the turn failed. Session events identify the actual runtime session. A fallback can replace that runtime session while the application session/turn remains stable. Emit tool starts before results and review requests before decisions. A review_request is both the proposal delivery and approval prompt. Emit error details before an error terminal event. Exactly one done closes each accepted turn, with status done, error, or cancelled. Emit events only for observed lifecycle transitions or actual adapter operations. Resume (0.4.5): when a turn stops on a model rate limit (HTTP 429) the adapter emits resumable (suggested wait, files already changed) before its error; the editor may then submit a new turn with resumeOf naming it, in the same session, with the original instruction. The adapter continues the same TrueForge conversation, tells the model what was already changed, and carries over what the interrupted turn used of both command budgets; a turn can be resumed once. Sub-agents (0.4.5): when TrueForge delegates to a sub-agent, the adapter emits subagent started and finished; a sub-agent's edits and commands go through the same review, budgets and cancellation as the main agent's, and its text is not part of the turn's reply. 0.4.6: the watchdog allows a longer silence while a model request is in flight (adapter option, default 120 s; 45 s for other waits), and a stall after the turn changed files is resumable (reason stalled); hunks carry deletes when they remove a whole class or function, which the review must show; done carries tests, the observed outcome of the last test command that ran (passed, failed with counts, or not_run), which the editor shows next to the model's summary.

Cancellation immediately closes the local approval gate, invalidates outstanding decisions and prevents further applies from starting. Repeating cancel on the same turn is safe. Confirmed cancellation produces terminal cancelled; an already completed turn retains its actual outcome. A timeout yields unconfirmed. Show that state and keep observing the stream; never infer cancellation from elapsed time or disconnection. Resolve an already submitted editor operation and report its actual outcome before terminal delivery. Keep previously applied edits undoable. Closing an active session returns conflict until its turn settles. Release listeners, queues and the MCP server on adapter disposal.

## Review and application

1. The MCP edit tool proposes one file. Register the immutable proposal against its session, turn, call and proposal IDs. For existing files hash the exact current editor buffer, including unsaved edits, using SHA-256 of UTF-8 text, lowercase hex, without adding a BOM or changing line endings. A new file requires absence and empty original text.
2. Hunk offsets are zero-based UTF-16 code units in the original text, with an exclusive end. Insertion has equal endpoints (including EOF); deletion has empty replacement. Require unique IDs, unambiguous ordered nonoverlapping ranges, exact old text, and reconstruction of proposedText from all hunks. Reject ambiguous same-position insertions. Selection and symbol line ranges are separately 1-based and inclusive.
3. Preview both versions. Require one decision for every known hunk ID and reject unknown IDs. Rejecting all denies the tool. The UI sends only a decision. The adapter orchestrates TrueForge approval and calls the private EditorBridge with the exact accepted IDs. The model has no apply tool. Denied, expired or ambiguous approvals fail closed.
4. The editor independently checks stored decisions, call identity, cancellation, path and the live base before applying. Serialize applies per document, guard against revision changes during application, and recheck absence on creation without overwrite. Apply the verified request.text in a single file operation. Replayed requests return the recorded outcome. Report stale on a mismatch and require fresh review. If safe creation cannot be guaranteed, reject it before mutation.
5. After successful application retain inverse ranges or the original snapshot locally, keyed by the undo receipt. Verify the post-edit hash before undo, including before removing an approved new file. Refuse conflicts. Buffer application, persistence and multi-file changes have distinct outcomes; never save unrelated dirty content implicitly. Terminal approval displays the exact command and working directory. Execution requires a matching one-use decision. Commands that would bypass reviewed file edits must be refused; an unrestricted shell cannot guarantee that property. The adapter sets command_request.unrestricted (with a warning) for anything outside its verification list, the editor must show that warning with the prompt, and the adapter reports any files a command changed (0.4.2). Since the merge of origin's execution protection (no protocol change), the adapter runs every approved command in bubblewrap with a read-only host filesystem and checkout, private temporary storage and no network, and refuses to run commands when that protection is unavailable; reads are not restricted. Optional auto-approval (0.4.3, off by default): with TurnRequest.autoApproveSafeCommands the adapter allows only listed commands itself and emits command_request with autoApproved, which the editor shows without prompting; unrestricted commands and edits always wait for the user. In 0.4.4 auto-approval covers only bare pytest, python -m pytest, git status and git diff. Command budget (0.4.4): TurnRequest.commandBudget (default 3 for agent, 1 for inline) caps the run_command calls a turn may present, prompted or auto-approved; later ones are refused to the model without a prompt and reported with command_budget_reached. Separate test-command budget (0.4.5): TurnRequest.testCommandBudget (default 3 for agent, 1 for inline) caps test runs (pytest, python -m pytest without shell operators), which no longer count against commandBudget; command_budget_reached.kind says which budget refused the call.

## EditorPort.applyText result

See edits.ts for the six result variants. After verifying live approval, expectedSha256 and textSha256, apply request.text in one conditional operation. The harness constructs this text. The editor never recomputes hunks. acceptedHunkIds are display/undo metadata. For a successful save, undo.expectedPostSha256 is the post-save buffer hash, including formatter changes.

- The first three outcomes establish that this invocation made no edit. They say nothing about unrelated changes. A null hash denotes an absent file. Validate live approval before reading or applying the proposal. Return stale for a verified base mismatch and failed_before_apply only when absence of mutation is established.
- After one successful conditional text edit, record the accepted IDs and undo receipt before attempting a save. All three Applied outcomes map to workspaceEffect **changed**. Buffer_applied is a final result when saving was deliberately deferred, for example because saving would persist unrelated unsaved user edits. In the usual apply-then-save flow, await the save before replying.
- On a false save result or exception, keep the live buffer, preserve the receipt and report a sanitized reason. Use unknown for disk state unless unchanged persistence has been verified. Offer inspection and retry of **save only**, or guarded undo. Refuse automatic recovery if the buffer has since changed. Duplicate requests return the recorded application state. Never replay hunks to retry persistence.
- Report saved only for a confirmed save of the identified document revision. Account for concurrent typing, auto-save and save participants before attributing a disk hash to that revision. If observation is lost after submission and mutation cannot be established, return an outer protocol error with workspaceEffect unknown and reconcile the document before retry. Review how save-time transformations affect guarded undo.
